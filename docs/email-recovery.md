# Email password recovery

Choose **Forgot password?** on the login screen. This feature is disabled until the server has an approved SMTP configuration, a dedicated random recovery secret and an exact HTTPS public origin. A global availability flag is shown by bootstrap; individual account registration is never returned. Requests for existing, unknown, suppressed or unavailable accounts use the same generic response. SMTP runs asynchronously; HTTP requests apply a small response-time floor and the existing per-address authentication budget. Account-level limits persist across restarts: at most three links in fifteen minutes, at least one minute apart. Requesting a link does not change the password or lock the account.

Links contain a random request ID and HMAC-SHA256 authenticator bound to the current account credentials and a server secret. Only hashes and request metadata are stored in SQLite. The worker derives the link while sending; raw tokens are not stored in the queue, returned by the request API or written to application logs. Public links use TW_PUBLIC_ORIGIN and never an incoming Host header. Links expire after fifteen minutes, work once, and are invalidated by password changes, operator recovery or recovery-key rotation. Completing one invalidates other outstanding links, revokes all account sessions, preserves MFA and memberships, and does not log the user in automatically.

The reset token is read from the browser URL fragment, removed from the address bar immediately and kept only in page memory. Reloading the reset page requires reopening the original email link. Passwords and tokens are sent in POST bodies to same-Origin endpoints. A disabled recovery gate also blocks completion. Existing MFA and single-use MFA recovery codes remain required on subsequent login.

## SMTP configuration

Keep real credentials outside Git and image layers. Configure TW_RECOVERY_ENABLED, TW_RECOVERY_SECRET (32-256 random characters), TW_PUBLIC_ORIGIN, TW_SMTP_HOST, TW_SMTP_PORT, TW_SMTP_SECURITY, TW_SMTP_FROM and optional TW_SMTP_USERNAME/TW_SMTP_PASSWORD. Username and password must both be set or both absent for a trusted authenticated-by-network relay. ssl uses implicit TLS, normally port 465; starttls normally uses port 587 and upgrades before authentication. Plain SMTP and disabled certificate verification are not supported. Use the placeholders in .env.production.example only as a template; replacement secrets are required. No real SMTP configuration was activated here.

The worker claims each submission once. A timeout or disconnection can leave delivery uncertain, so it is never automatically retried. A crash after claiming also requires a new request. A link already delivered can still be used if valid, even when SMTP submission ended uncertainly. Transport acceptance is not proof of inbox delivery. Configure sender authentication, SPF/DKIM/DMARC and mailbox acceptance on the deployment host. TLS/SMTP tests use controlled transports; real delivery remains unverified. Reset metadata older than seven days past expiry is pruned during enabled recovery requests. Password-change alert emails, SSO and a full account-verification lifecycle remain separate work.

Reference design: OWASP Forgot Password Cheat Sheet and Python smtplib documentation. This is not a claim of a completed independent security audit.
